# Bricksmith Models

## Default: full-catalog native scenes

1. **Interpret the subject.** Inspect the actual image, or extract the requested object's silhouette, proportions, characteristic parts and colors from text. Choose a model scale and budget. State inferred unseen geometry. The host agent authors the design; the tools are deterministic. Completion: a specific three-dimensional brief, not an enlarged pixel grid or an example preset substituted for the request.

2. **Resolve the full library.** Read `references/setup.md`, locate the companion tools and an installed full LDraw library, then run `node <tool-root>/tools/bin.mjs library status --library <library-root>` and `scene schema`. Install/index through the documented tools only if missing; reuse the local cache. Read `references/full-catalog.md` for commands and units. Completion: verified library provenance, schema and budgets; distinguish the full official community library from LEGO's exhaustive commercial inventory. The legacy `catalog` command returns only the optional 14-part voxel subset.

3. **Search before selecting and place actual parts.** Run `parts search --library <library-root> --query <terms> --limit 30`, optionally `--category <category>`; paginate with `--offset`. Inspect selected IDs with `parts inspect --library <library-root> --id <id>` and obtain colors with `parts colors --library <library-root>`. Write a new `bricksmith.scene.v1` scene using inspected main IDs, explicit colors, native-LDU positions and proper rotation matrices. Use actual curved/sloped/wedge/round pieces where they serve the silhouette; do not inflate counts or substitute boxes for their geometry. Completion: a composed 3D scene of real selected parts with explicit transforms, not just a catalog list or separated parts display.

4. **Check, render and revise.** Run `scene validate --library <library-root> --scene <scene.json>`, then `scene render --library <library-root> --scene <scene.json> --out <new-views-dir> --size 1100`. Open iso/front/side/back PNGs; compare silhouette, joins, proportions and orientation to the brief and previous revision. Inspect `render.json` for errors, missing resources and geometry evidence. Fix placements and save each revision separately. Dependencies missing from the actual library and unsupported TEXMAP rendering must remain explicit failures, not blank or fabricated geometry. Completion: real catalog meshes visually inspected with no hidden rendering errors. Keep requested persistent preview servers stopped; rendering uses only its temporary loopback server.

5. **Export the inspected scene.** Run `scene export --library <library-root> --scene <scene.json> --out <new-export-dir>`. Verify scene.json, model.ldr, inventory.csv, report.json, library-manifest.json and the unchanged dependency/license subset. Preserve the library digest and real references. Supply `assemblyOrder` only if deliberately authored; arbitrary mesh order is not a building guide. Completion: an export matching the checked scene with source/license integrity retained.

6. **Deliver qualified results.** Attach an inspected PNG and portable model/tool package. State actual placements and distinct IDs; explain that physical connections, collisions, stability and part/color availability are unverified. Do not apply the rectangular voxel checker to arbitrary meshes, call visual contact a legal connection, or describe a catalog-scene validation pass as proof of buildability. Report remaining gaps/overhangs. Note any missing-dependency/TEXMAP limitations separately from whole-library availability. Completion: usable files plus the verification actually performed, without claiming physical instructions or a certified kit.

## Optional: legacy rectangular voxel workflow

Use this branch when the user explicitly wants block/voxel sculptures or is editing a prior `bricksmith.design.v1` model. Preserve its source and exact repaired plan; these coordinates and validators differ from native scenes.

1. **Inspect and interpret.** Open the actual reference image with the host's image-reading capability, or extract the subject/features from the text. Identify silhouette, characteristic features, colors and depth cues. State inferred unseen geometry and scale. Choose a modest stud size and piece budget unless specified. The current host agent designs the model; the companion tools perform deterministic geometry processing. Completion: a specific volumetric 3D brief rather than a pixel-heightmap or preset substitution.

2. **Resolve and inspect the tools.** Locate the companion Bricksmith package using `references/setup.md`. Run `node <tool-root>/tools/bin.mjs catalog` and `node <tool-root>/tools/bin.mjs schema`. Completion: the real catalog, design schema and resource caps are returned. Report missing dependencies as setup blockers; no separate model login or API credential is needed by these tools.

3. **Author source geometry.** Write `design.json` in the task output directory, conforming to the returned schema. Use boxes, ellipsoids, cylinders, constructive-solid operations and explicit voxel overrides for genuinely new subjects. Read `references/design.md` for axes and material semantics. Use returned catalog colors; add bases/braces as explicit visible geometry where needed. Keep private reference images out of reusable packages. Completion: geometry expresses the brief in three dimensions within the chosen budget.

4. **Compile and diagnose.** Run `node <tool-root>/tools/bin.mjs compile --design <design.json> --out <revision-dir>`. Read stdout and `report.json`; exit 3 retains inspectable outputs with structural/fidelity defects. Correct schema/budget errors before proceeding. Completion: an actual part-based `plan.json` and reviewed issue list.

5. **Render, inspect and repair.** Run `node <tool-root>/tools/bin.mjs render --plan <revision-dir>/plan.json --out <revision-dir>/views`. Open `iso.png`, `front.png` and at least one side/back view. Compare recognizability and proportions with the reference/brief. Use issue codes, piece IDs and suggested actions to repair explicit source geometry; recompile into a fresh revision directory. For correct geometry stranded by greedy seams, instead repack the affected same-color course: pin a catalog plate that bridges lower contacts or components, remove intersecting same-course plates, and cover every remaining cell with catalog rectangles. Accept only repairs that preserve all target cells/colors and reduce unsupported/component errors without worsening either count or introducing collisions. Where a thin curved rim has diagonal-only contacts that cannot be bridged by rectangles, author explicit rim landings in the source before recompiling. Record removed IDs and replacement placements; retain the repaired final plan and replay those edits on a fresh compile to verify identical output. A raw recompile alone does not preserve manual seams. Resolve collisions, unsupported pieces, disconnected groups and fidelity errors where feasible; retain partial-support warnings. Bound iteration to a few revisions and deliver an explicitly labeled draft if defects remain. If browser or image inspection is unavailable, report visual verification as blocked. Completion: rendered 3D form reviewed and remaining defects documented.

6. **Validate and export the same revision.** Run `node <tool-root>/tools/bin.mjs validate --plan <revision-dir>/plan.json --design <design.json> --out <revision-dir>/recheck.json`, then `node <tool-root>/tools/bin.mjs export --plan <revision-dir>/plan.json --design <design.json> --out <revision-dir>/export`. Pair the exact design with its compiled plan. Read the final report and verify files exist. Completion: model.ldr, inventory.csv, instructions.html, plan.json and report.json from one checked revision.

7. **Deliver usable artifacts with evidence.** Attach an inspected preview, source design and export bundle. Report actual piece count, connected groups, collisions, unsupported pieces and warnings. Instructions are HTML unless a PDF was actually generated. Explain that image-guided hidden geometry is inferred; fidelity checks compare sampled colored voxels, not likeness. Geometric checks do not establish physical strength, clutch behavior, insertion paths or part/color stock. LDraw consumers require their standard parts library. Completion: files and qualified verification reach the user, rather than only status or local paths.
