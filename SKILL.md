# Bricksmith Models

1. **Interpret the subject.** Inspect the actual image, or extract the requested object's silhouette, proportions, characteristic parts and colors from text. Choose a model scale and budget. State inferred unseen geometry. The host agent authors the design; the tools are deterministic. Completion: a specific three-dimensional brief, not an enlarged pixel grid or an example preset substituted for the request.

2. **Resolve the full library.** Read `references/setup.md`, locate the companion tools beside this skill and an installed full LDraw library, then run `node <tool-root>/tools/bin.mjs library status --library <library-root>` and `scene schema`. For host setup use `references/openclaw.md` or `references/astra.md`. Install/index through the documented tools only if missing; reuse the local cache. Read `references/full-catalog.md` for commands and units. Completion: verified library provenance, schema and budgets; distinguish the full official community library from LEGO's exhaustive commercial inventory.

3. **Search before selecting and place actual parts.** Run `parts search --library <library-root> --query <terms> --limit 30`, optionally `--category <category>`; paginate with `--offset`. Inspect selected IDs with `parts inspect --library <library-root> --id <id>` and obtain colors with `parts colors --library <library-root>`. Write a new `bricksmith.scene.v1` scene using inspected main IDs, explicit colors, native-LDU positions and proper rotation matrices. Use actual curved/sloped/wedge/round pieces where they serve the silhouette; do not inflate counts or substitute boxes for their geometry. Completion: a composed 3D scene of real selected parts with explicit transforms, not just a catalog list or separated parts display.

4. **Check, render and revise.** Run `scene validate --library <library-root> --scene <scene.json>`, then `scene render --library <library-root> --scene <scene.json> --out <new-views-dir> --size 1100`. Open iso/front/side/back PNGs; compare silhouette, joins, proportions and orientation to the brief and previous revision. Inspect `render.json` for errors, missing resources and geometry evidence. Fix placements and save each revision separately. Dependencies missing from the actual library and unsupported TEXMAP rendering must remain explicit failures, not blank or fabricated geometry. Completion: real catalog meshes visually inspected with no hidden rendering errors. There is no standalone web app to start; PNG rendering uses its temporary loopback server and closes it afterward.

5. **Export the inspected scene.** Run `scene export --library <library-root> --scene <scene.json> --out <new-export-dir>`. Verify scene.json, model.ldr, inventory.csv, report.json, library-manifest.json and the unchanged dependency/license subset. Preserve the library digest and real references. Supply `assemblyOrder` only if deliberately authored; arbitrary mesh order is not a building guide. Completion: an export matching the checked scene with source/license integrity retained.

6. **Deliver qualified results.** Attach an inspected PNG and portable model package. State actual placements and distinct IDs; explain that physical connections, collisions, stability and part/color availability are unverified. Do not call visual contact a legal connection or describe a catalog-scene validation pass as proof of buildability. Report remaining gaps/overhangs. Note any missing-dependency/TEXMAP limitations separately from whole-library availability. Keep private reference images out of reusable packages. Completion: usable files plus the verification actually performed, without claiming physical instructions or a certified kit.
